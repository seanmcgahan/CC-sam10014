# Projection Mapping Process

I rented out a projector from the IDM equipment room to use for the assignment this week. I was at my parent's house in NJ for the weekend so I set it up in the basement with a bunch of random cardboard boxes that I found sitting around. They were brown cardboard but still worked to project onto, especially with the lights off. 

I started the first part of the assignment by setting up the boxes so that I had 7 different faces to project onto (labelled 0-6). I put sticky notes on each and wrote the code for the colors I needed. Once I had my projector callibrated and focused at the right angle to project onto the boxes, I simply went in and adjusted the orientation of each to match the faces of the boxes. This worked pretty smooth and was easy to do.

I next moved on to adding sketches onto the boxes. When starting this process, I originally didn't take into account that the boxes I was using were not perfect squares. Because the sketches I was putting on each box were 400x400, this resulted in the images being stretches or squashed a bit when projected out on the boxes. I noticed this however and went back into the code for each sketch, adjusting the dimensions to appropriately fit each box face. This required either adding more width/less width for each sketch, and moving the elements themselves appropriately as well. After these changes, going back and reprojecting them onto the box faces went much better and the sketches were represented correctly.

The only other issue I ran into was that with 7 different sketches all running (and most of them having moving elements in them) resulted in some lag when loading them in browser, which is understandable. This was good to know and I will definitely keep this in mind in the future if doing more projection mapping or other WEBGL designs.
